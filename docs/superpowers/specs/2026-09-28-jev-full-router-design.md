# EXPRESS-Bench Jev Full Router Design

## Goal

Add a Jev-controlled decision layer to EXPRESS-Bench while preserving the
existing Fine-EQA perception and Habitat execution stack. Provide a second
oracle-semantic upper-bound condition and enough structured logs to compare
the two conditions with the original baseline.

## Scope

The online Jev-full-router evaluates the current question, history, VLM
outputs, TSDF map summaries, and executable GOE/FBE candidates. It asks Jev
for three independent decisions in one request: whether to stop, which mode to
use, and which candidate to target. Jev never receives the reference answer,
goal pose, reference trajectory, geodesic target distance, or raw images.

RGB images remain inputs to the local VLM. The VLM and TSDF convert them into
text and numeric summaries before Jev is called. The final answer remains
generated by the local VLM because Jev returns typed decisions rather than
free-form strings.

The oracle-semantic condition is an explicit upper-bound ablation. It may use
Habitat semantic observations or scene semantic assets to provide ground-truth
category/object evidence, but it is labeled privileged and is never mixed with
the main fair condition.

## Components

### `Jev_scripts/jev_client.py`

An environment-keyed HTTP client for `POST
https://api.typesafe.ai/v1/systemone`. It validates the key before a call,
serializes JSON state and typed questions, applies bounded retries and timeout,
parses answers/probabilities/confidence, and records latency, token usage, and
fallback-relevant errors. It does not log the API key or raw images.

### `Jev_scripts/decision_router.py`

Defines a JSON-serializable state schema and builds the `stop`, `mode`, and
`target` questions. It applies thresholds and candidate feasibility checks to
the typed Jev response. Any API, schema, timeout, or confidence failure uses a
deterministic Fine-EQA-compatible fallback. The router supports `fair` and
`oracle_semantic` evidence labels and never accepts ground-truth answer or
goal fields in its state builder.

### `Jev_scripts/tsdf_candidates.py`

Small adapters that summarize existing `TSDFPlanner.exp_list` and frontier
statistics. They expose stable candidate ids and numeric features for Jev and
retain the planner's selected point/path execution semantics. Candidate
enumeration is bounded to keep requests compact.

### `Jev_scripts/run_jev_replay.py`

Replays existing episode/result artifacts where possible, exercises the router
with deterministic fixture states, and writes JSONL step decisions plus CSV
and JSON aggregate summaries. This is a low-cost API/reproducibility check;
online Habitat runs use the same router interface.

### Optional `main.py` hook

The main loop receives an opt-in configuration block. With Jev disabled, all
existing behavior is unchanged. With Jev enabled, the loop calls the router
after perception and candidate generation, uses the returned action to select
stop/GOE/FBE/target, and persists the decision trace into each result.

## Decision protocol

The state contains only online-observable or locally derived information:

- question and question type;
- step, budget, path length, and recent actions;
- normalized VLM stop/region/point scores and semantic scores;
- explored ratio and TSDF-derived GOE/FBE candidates.

The `stop` Noul is eligible to terminate only when its probability and
confidence thresholds pass. If it does not stop, `mode` chooses GOE or FBE
among available candidates; `target` chooses a candidate id. A missing or
invalid choice falls back to the original rule and planner selection.

## Experimental conditions

Report at least:

1. Original Fine-EQA baseline.
2. Jev-stop-only (optional isolation ablation).
3. Jev-full-router with fair RGB/VLM/TSDF evidence.
4. Jev-full-router with oracle semantic evidence (privileged upper bound).

Keep seed, question split, model checkpoints, prompts, sensor settings, and
step budget fixed. Sweep the stop threshold over 0.60, 0.75, and 0.90. Report
the existing `C_avg`, `C_star_avg`, `E_path`, and `d_T_avg`, plus answer step,
stop rate, GOE/FBE share, Jev latency/call count/token usage, and fallback rate.
Use paired bootstrap confidence intervals by question and stratify by question
type and target region.

## Failure handling and reproducibility

The API client retries only bounded transient failures. Any final failure is
recorded and immediately falls back to the baseline action, so a network or
service issue cannot silently terminate an episode. Every decision log stores
the schema version, router mode, threshold, candidate ids, selected action,
fallback reason, and response metadata. Secrets are read only from
`TYPESAFE_API_KEY`.
